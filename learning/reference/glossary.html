Glossary

The repo's nomenclature, one line each, with where it lives. Every lesson uses these terms exactly as defined here.

TermMeaningLives in
JourneyOne approved customer task (J1 = one-time payment, J2 = set up AutoPay, … J5 = cancel payment), defined in the design plan.plans/agent-simulator-design-plan.md
FixtureThe single frozen dataset (cards …9013/…0767/…4421, accounts, AutoPay, scheduled payments, frozen "now") that both the mock bank and the customer's knowledge are generated from.fixtures/paycard.py
RegistryThe canonical tool names (PayeeList, AddValidateOneTimePayment, …) shared with the real agent, so tests transfer without renames.agentsim/registry.py
MessageOpenAI-style {role, content} dict — the lingua franca between every component.agentsim/types.py
AdapterThe seam: one async call(AgentInput) → AgentResponse. The agent-under-test is a black box behind it (mock today, HTTP tomorrow).agentsim/adapters/base.py
Agent-under-testThe payment assistant being probed — MockPayCardAgent (with plantable defects) or the real agent over HTTP.agentsim/adapters/
User simulatorRole-reversed LLM playing the customer: persona + goal + grounded knowledge, per-turn re-injection, ###STOP### sentinel.agentsim/simulator.py
ScenarioOne test card: journey, persona, goal, knowledge slice, success criteria, tool assertions, max_turns. YAML in scenarios/ or generated.agentsim/scenario.py
JudgeLLM referee returning a forced structured verdict per criterion; fail-closed — only an explicit true passes.agentsim/judge.py
AssertionDeterministic tool-structure check (e.g. validated_submit: validate before submit) — code, not LLM.agentsim/assertions.py
TraceThe immutable record of what happened in a run; verdicts are derived from it, never stored in it.agentsim/trace.py
OrchestratorThe turn loop: simulator → agent → judge until verdict, ###STOP###, or max_turns (which fails closed as task_incomplete).agentsim/orchestrator.py
Script / DSLPinned opening turns and checkpoints that share the same machinery as autonomous simulation.agentsim/script.py
Procedure graphThe journey as a checked map: nodes = steps, edges = legal moves carrying tools, policies, curveball slots, turn costs, and source hashes.scenario_synthesis/procedures/j1.yaml
PolicyA journey-borne rule worth testing (explicit_confirmation, tool_output_truth, card_switch_resets, disambiguate_last_four) with its enforcement mapping.scenario_synthesis/policies.py
Perturbation (curveball)A planned surprise declared on one edge with an executable trigger, acted out via the customer or data; max two per blueprint.procedures/j1.yaml
BlueprintThe structured skeleton of a test (path, policies, bindings, goal facts, perturbations, provenance) — facts only, no prose.scenario_synthesis/blueprint.py
RealizationLLM writing a blueprint into scenario YAML, guarded to be fact-equivalent — retried on any invented detail.scenario_synthesis/realize.py
Dry runPlaying each candidate twice — faithful mock (should pass) and defects-on mock (should fail) — recorded, never used to filter.scenario_synthesis/dryrun.py
Planted defectOne of seven deliberate bugs (D1–D7) toggleable in the mock; the acceptance test is that all seven surface in the report.agentsim/adapters/mock_paycard/
ClusteringTwo-stage grouping of failures into ranked unique bugs mapped back to journeys, invariants, and reproducing chats.agentsim/clustering.py
