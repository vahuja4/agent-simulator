The Adapter Seam

One tangible win: after this lesson you can explain why the entire test suite swaps a mock assistant for the real one with ~30 lines of code — and read the loop that makes it true.

The one interface everything hangs on

The core loop never knows what it's testing. It only knows this contract, from agentsim/adapters/base.py (whose docstring opens, literally, with "The seam."):

class AgentAdapter(ABC):
    @abstractmethod
    async def call(self, input: AgentInput) -> AgentResponse: ...

One async method. In: the conversation so far. Out: the assistant's next reply. Everything else — mock vs real, stateful vs stateless — is the adapter's private business, keyed by AgentInput.conversation_id.

What crosses the seam

Two small dataclasses in agentsim/types.py — whose docstring calls OpenAI-style message dicts "the lingua franca between every component":

TypeCarriesThe non-obvious bit
AgentInputconversation_id + the Message list (role/content)Multi-turn state is the adapter's problem, not the loop's.
AgentResponsereply content + tool_calls + selected_cardEach ToolCall carries its result — judges and assertions need results, not just calls.

The loop that drives it

agentsim/orchestrator.py runs: simulator → adapter → judge, turn after turn, until the customer sends ###STOP###, the judge reaches a verdict, or max_turns runs out. One design decision to remember — it's fail-closed:

Design decision

Reaching max_turns without goal completion is recorded as task_incomplete — a failure, never a shrug. Same spirit as the judge: a criterion passes only on an explicit true. Silence never passes anything.
